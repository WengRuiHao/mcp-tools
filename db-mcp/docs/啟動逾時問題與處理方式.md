# db-mcp 啟動逾時（CONNECT_TIMEOUT）問題與處理方式

> 撰寫日期：2026-10-27
> 給接手處理的 AI：本文件獨立完整，不需要看原本的對話。「已驗證」的項目有實測數據；「未驗證」的項目請不要當成事實。
> 專案位置：`C:\Tool\mcp-tools\db-mcp`（`C:\Tool\db-mcp` 是指向它的 junction）

## 1. 症狀

Claude Code 視窗啟動（或重新載入 MCP）時，`db-mcp` 偶爾顯示：

```
MCP server "db-mcp" connection timed out after 30000ms   (CONNECT_TIMEOUT)
```

使用者的描述：「每次啟動 LINE Bot 的服務，我的 db-mcp 都會斷線」。

- 發生時，**同一台電腦上其他 Claude 視窗的 `db-mcp` 一直正常**（持續成功執行 `db_query`）。
- 同一時間啟動的其他 MCP（asana、dev-pipeline、github、gitlab-mcp、office-docs）都連上了，**只有 `db-mcp` 逾時**。
- 逾時當下 Claude 的日誌（`%LOCALAPPDATA%\claude-cli-nodejs\Cache\C--Tool\mcp-logs-db-mcp\*.jsonl`）只有：
  - `Starting connection with timeout of 30000ms`
  - stderr：`ExperimentalWarning: SQLite is an experimental feature`（這是 `node:sqlite` 被載入時的正常警告）
  - 30 秒後 `Connection failed ... (CONNECT_TIMEOUT)`
  - 沒有任何錯誤或例外，也就是**程序沒有崩潰，只是 30 秒內沒有完成 MCP 握手**。

## 2. 根本原因（已驗證）

`db-mcp` **啟動時會同步載入全部四個資料庫驅動**，不論這次連線用不用得到。以下是在這台電腦（Windows 11、Node 22.15.0、nvm4w）量到的載入時間：

| 模組 | 載入時間（第一次） | 載入時間（第二次，檔案快取已暖） |
|---|---|---|
| `mssql` | 3769 ms | 4132 ms |
| `mysql2` | 1851 ms | 702 ms |
| `oracledb` | 323 ms | 850 ms |
| `pg` | 499 ms | 263 ms |
| `node:sqlite` | 約 0 ms | 約 0 ms |

驅動都是**頂層 import**，位置：

- `src/drivers/mssql.ts:1`  `import sql from "mssql";`
- `src/drivers/mysql.ts:1`  `import mysql from "mysql2/promise";`
- `src/drivers/oracle.ts:1` `import oracledb from "oracledb";`
- `src/drivers/postgres.ts:1` `import pg from "pg";`

`src/index.ts` 本身很單純（建立 `StdioServerTransport` 後立刻 `server.connect`），所以握手時間幾乎等於「所有模組載入完」的時間。

### 實測：啟動到完成 MCP `initialize` 握手的時間

| 情境 | `db-mcp` | 對照：`dev-pipeline-mcp` |
|---|---|---|
| 電腦閒置，第 1 次（冷） | **18891 ms** | — |
| 電腦閒置，第 2 次 | 6567 ms | 2830 ms |
| 電腦閒置，第 3 次 | 6822 ms | — |
| 同時另一個程序在編譯並啟動服務 #1 | 11977 ms | 2185 ms |
| 同上 #2 | 13699 ms | — |
| 同上 #3 | 5274 ms | — |

Claude Code 對 MCP 的連線上限是 **30000 ms**。`db-mcp` 平常就用掉其中 6 到 19 秒，只要電腦同時忙一點（多個 MCP 一起啟動、編譯、防毒掃描新檔案、冷快取），就可能越線。

## 3. 已排除的原因（已驗證）

| 假設 | 結論 |
|---|---|
| 與 LINE Bot 服務搶同一個連接埠 | 否。`db-mcp` 的 stdio 模式不監聽任何埠；`start:http` 才用 9096，且預設不啟動。Bot 用 3000 |
| SQLite 檔案鎖 | 否。`openSchemaDb()` 只在呼叫工具時才開檔，啟動時不開 |
| 設定被工作目錄影響 | 否。`db-mcp` 設定在 `~/.claude.json` 的**使用者層級**（全域），不是專案層級 |
| 程序被殺掉 | 日誌只有 `ExperimentalWarning` 與逾時，沒有崩潰或結束碼 |
| 程式碼啟動時卡在連線資料庫 | 否。`index.ts` 啟動流程沒有連資料庫 |

## 4. 未驗證（請不要當成事實）

- **LINE Bot 的啟動是否為觸發原因：未證實。** 實驗顯示 Bot 啟動期間 `db-mcp` 握手多花約 2 到 7 秒，是「加重因素」，但單靠它沒有把握手推過 30 秒。比較可能的觸發是 Claude 視窗啟動時所有 MCP 同時啟動。
- 防毒軟體（Windows Defender）即時掃描是否拖慢載入：未量測。
- 同機器有 Claude 視窗 `C:\Tool`、`C:\SCSB`、`C:\bokeps`、`C:\bokeps\bokeps-ReportService` 等多個，視窗同時啟動時的競爭程度：未量測。

## 5. 建議的處理方式

### 方案 A（推薦，根本解法）：驅動改成「用到才載入」

目標：啟動時不載入任何資料庫驅動，改在第一次真的要用該類型連線時才 `await import()`。預期握手時間降到 1 到 2 秒。

實作方向：

1. 檢視 `src/db-client.ts` 與 `src/drivers/*.ts`，找出各驅動被建立與使用的入口。
2. 把 `import sql from "mssql"` 等頂層 import 改為在驅動函式內部 `const { default: sql } = await import("mssql")`，並用模組層級的變數快取，避免重複載入。
3. 型別只用 `import type`，避免型別 import 造成實際載入。
4. 保持行為不變：連線測試、查詢、取得 schema 的結果與錯誤訊息都不能改。
5. **不要動 `src/readonly-gate.ts`**。「只放行 SELECT/WITH/SHOW/DESCRIBE/EXPLAIN」是刻意的安全設計，與本問題無關。

### 方案 B（輔助，治標）：放寬 MCP 連線上限

在 Claude Code 的設定加入環境變數 `MCP_TIMEOUT`（單位毫秒），例如 `60000`。

- **請先查證 Claude Code 目前版本是否支援這個環境變數名稱與單位**，我是憑印象寫的，沒有驗證過。
- 這只是給更多時間，沒有解決載入慢的根本原因，建議搭配方案 A。
- 這會修改使用者的 Claude 設定（`~/.claude/settings.json` 的 `env`），**要先取得使用者同意**。

### 建議順序

先做方案 A；做完後若仍想保險，再詢問使用者是否加方案 B。

## 6. 驗收標準

用下方量測腳本，在**電腦閒置**時連續量 5 次，並在**同時有編譯或其他程序在跑**時量 3 次：

| 項目 | 目標 |
|---|---|
| 握手時間（閒置，5 次） | 每次 < 3000 ms |
| 握手時間（有負載，3 次） | 每次 < 5000 ms |
| 功能不變 | 至少對一個實際可連的資料庫成功執行 `db_list_connections`、`db_schema`、`db_query`（SELECT） |
| 唯讀閘門 | 送出 `INSERT`／`UPDATE`／`DELETE` 等寫入語句仍被拒絕 |
| 型別與建置 | `npm run build` 無錯誤 |

注意：量測時請**只啟動與關閉你自己啟動的 `db-mcp` 程序**。這台電腦上有很多 `node.exe`（其他視窗的 MCP 伺服器），**不要用 `taskkill /IM node.exe`**，也不要關閉不是你啟動的程序。

## 7. 量測腳本

存成 `mcp-handshake-time.mjs`，用 `node mcp-handshake-time.mjs C:/Tool/db-mcp/dist/index.js 標籤` 執行。它會啟動一份 MCP 伺服器、送出 `initialize` 請求，量測到收到回應的時間，然後關掉自己啟動的那一份。

```js
import { spawn } from 'node:child_process';

const TARGET = process.argv[2] ?? 'C:/Tool/db-mcp/dist/index.js';
const TIMEOUT_MS = 60_000;
const label = process.argv[3] ?? '';

const started = performance.now();
const child = spawn(process.execPath, [TARGET], { stdio: ['pipe', 'pipe', 'pipe'] });

let stderrFirstAt;
child.stderr.on('data', () => {
  stderrFirstAt ??= performance.now() - started;
});

child.stdin.write(
  JSON.stringify({
    jsonrpc: '2.0',
    id: 1,
    method: 'initialize',
    params: { protocolVersion: '2024-11-05', capabilities: {}, clientInfo: { name: 'handshake-probe', version: '1.0.0' } },
  }) + '\n',
);

const timer = setTimeout(() => finish('逾時（>' + TIMEOUT_MS / 1000 + 's）'), TIMEOUT_MS);
let buffer = '';
child.stdout.on('data', (chunk) => {
  buffer += chunk.toString('utf8');
  if (buffer.includes('"id":1')) finish('握手成功');
});
child.on('exit', (code) => finish(`程序提前結束 code=${code}`));

let done = false;
function finish(result) {
  if (done) return;
  done = true;
  clearTimeout(timer);
  const elapsed = Math.round(performance.now() - started);
  const warn = stderrFirstAt === undefined ? '無' : `${Math.round(stderrFirstAt)}ms`;
  console.log(`${label} ${result}：${elapsed}ms（第一次 stderr 輸出：${warn}）`);
  child.kill();
  setTimeout(() => process.exit(0), 200);
}
```
