二、願景與三種粒度

把目前只服務 Asana 票單的流程，泛化成可支援 greenfield／brownfield 的流程引擎。同一份 workflow 定義用 granularity 決定層級，並以 children 遞迴展開。

feature（功能）
最小單位。現有 Asana 票單流程等價於此層。
module（模組）
由 SA 規格的功能清單展開成多個 feature。
system（系統）
先做模組切分，再展開成多個 module。切分錯誤會全部重工，屬硬停點。

Greenfield／Brownfield 是同一套流程的旗標（baseline），不是兩套流程。brownfield 才啟用「現況盤點／影響分析師」。

三、角色與流程

主線（依賴順序）

現況盤點／影響分析（僅 brownfield）→ SA 分析師→ DB 設計師→ 流程分析師→ SD 分析師→ 規格驗證師（驗證 SA↔SD 能串起來）→
前端工程師（依 SA，規格驗證通過後開工）∥ 後端工程師（依 SD，SD 確認後才能開工）→ 驗證師（兩者都完成）→ 測試工程師（白箱→黑箱，截圖留證）→ 人工最終驗收（鎖死 manual）

虛線＝可選／條件式角色。純前端或純後端的需求，對應角色標 optional 略過，驗證師只驗存在的那一邊。

規格先行：不靠 Asana 的新流程一律「SA、SD 規格確認並通過規格驗證，才能開發」，沒有先寫程式再補規格這條路。「先程式、後補規格」（code_first）只保留在 Asana 票單的舊流程（legacy-adapter），舊的階段排序表不動。

六、確認開關與硬停點

每道關卡有自己的 confirmMode：manual（停下來等你）、auto（各 agent 分工、主 Agent 判斷）、inherit（跟隨上層，預設）。層級：workflow 預設 → 專案 flow.json 覆寫 → 單一關卡覆寫。

auto 的安全設計

  • 審查者與作者分離：auto 時由獨立審查子 Agent（帶檢查清單）審產出物，不讓同一個模型自寫自審。
  • 決定留紀錄：確認紀錄加 confirmedBy: "human" | "agent"，附審查理由與清單結果。
  • 硬停點：auto 也不能略過（下表）。
  • 最終人工驗收：locked，不可設為 auto。
#HardStopId情境
1destructive-db破壞性 DB 異動（drop／改欄位型別／刪資料）
2breaks-existing影響分析判定會破壞既有功能
3consecutive-fail-3連續 FAIL 3 次
4reviewer-uncertain審查子 Agent 回報「不確定」或規格有矛盾
5scope-split模組切分（系統層）這類一錯就全部重工的決策
6sensitive-data敏感資訊攔截命中

與現有硬規則一致：不確定就停下來問、略過 SD 只能依使用者原話。auto 不能凌駕這些規則。

七、Schema 草案（schemaVersion: 1）

interface WorkflowDefinition {
  schemaVersion: 1;
  id: string;                                   // "asana-ticket"、"module-brownfield"
  granularity: "feature" | "module" | "system";
  source: "asana" | "manual";
  baseline: "greenfield" | "brownfield";
  confirmDefault: "manual" | "auto";
  hardStops: HardStopId[];                      // workflow 層級，auto 也不能略過
  artifacts: ArtifactDef[];
  roles: RoleDef[];
  gates: GateDef[];
  children?: { from: string; workflow: string };
}
interface ArtifactDef { id; file; kind: "markdown"|"mermaid"|"sql"|"report"|"code-change";
  attachments?; render?; evidence?: ("screenshot")[] }
interface RoleDef { id; promptRef; dependsOn: string[]; parallelWith?; inputs; outputs;
  optional?; when?: string /* 只支援 key==value，可用 && 連接 */ }
interface GateDef { id; after: string|string[]; type: "confirmation"|"content"|"verdict"|"evidence";
  confirmMode?: "manual"|"auto"|"inherit"; locked?; checks?; routeOnFail? }

專案 flow.json 覆寫規則：只能覆寫 confirmMode、optional、content 關卡的 checks、角色補充說明（roleNotes）；不能移除 locked 關卡與 hardStops，也不能改角色依賴順序。
