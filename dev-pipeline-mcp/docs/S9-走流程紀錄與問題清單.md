## 三、接續方式
1. 檢查暫存專案裡 `src/`、`public/`、`tests/` 是否完整；後端須有 `date-utils.js`、`order-query.js`、`http-errors.js`、`auth.js`、`xlsx-writer.js`、`db.js`、`server.js`、`scripts/seed.js`、`package.json`；前端須有 `public/index.html`、`public/app.js`、`public/logic.js`。
2. 在暫存專案跑 `node --test`，確認通過。
3. 用 `work_item` 的 `write` 寫 `impl-be.md`、`impl-fe.md`（各自要有「## 改動檔案」條列與「## 重用檢查紀錄」表格；有需要時加「## 重複豁免」），再 `done` 交件；交件時會自動跑重複程式碼偵測並寫出 `dup-report.md`。
4. 驗證師（獨立 agent）、測試工程師（含瀏覽器截圖放 `evidence/`，`test.md` 要有「## 白箱」「## 黑箱」與「## 測試：」標題並引用截圖）。
5. 最終驗收：**一定要使用者本人說確認**，並附原話。

## 四、驗證到運作正確的機制
- 技術確認、mockup 確認：只有使用者能確認，AI 代確認被擋下。
- 程式檢查在交件時把關：技術棧、截圖、SA 不寫程式、「重用與共用設計」標題。
- 獨立審查員（共 8 位以上）每一位都找到真實問題，或如實放行。
- 審查員申報「不確定」或「範圍切分」時，AI 不能代為確認，由使用者決定。
- 規格驗證判定：AI 可以直接裁決「不通過」，依根因自動退回 SD 並倒回下游；連續失敗次數會累計。
- 選用的內建產圖功能（Playwright）沒安裝時，回傳清楚的原因與替代做法（AI 自己截圖再附上），流程圖與截圖都改用 Edge 瀏覽器產生後以 `attach` 存入，成功。
