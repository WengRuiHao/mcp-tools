# SA／SD 撰寫標準範本

使用者在實際走完一次規格先行流程後確認：「目前這樣就是完整版，SA、SD 就要依照這個等級去撰寫」。這個資料夾是確認過的標準範本，之後所有 SA、SD、資料表結構文件都以此為準。

## 範本檔案
| 檔案 | 用途 |
|---|---|
| SA-範本.md、SA-範本.docx | SA（客戶版）的樣子；docx 是由 md 轉出的 Word 版 |
| SD-範本.md | SD（自足版）的樣子 |
| 資料表結構文件-範本.md | 資料表結構文件（分組：有關聯的表同一份，單獨的表各一份；內含 orders 加 order_items 同組、members 單表兩份文件） |
| 系統ER圖-範本.md | 系統 ER 圖文件（TableSchema/system-er.md）的樣子 |
| er/ | 範本引用的 ER 圖 PNG（模組圖 orders.png、members.png，系統圖 system-er.png；路徑相對於文件） |
| mockup-狀態切換範例.html | 可切換狀態的 mockup 範例，用來截各種狀態的畫面 |
| sa-images/ | 範本引用的畫面截圖（整體畫面與各種狀態，路徑相對於文件） |
| tools/md2docx.py | md 轉 Word 的原型（python-docx，支援圖片、表格、標題） |

## SA 標準（給客戶看）
1. 不可有工程或程式用語，不可有空洞章節（例如「已確認的決定」「依據附錄」「純後端」「共用畫面元件」），不可寫「說明這段文字為什麼存在」的句子。
2. 有基本資料表與版本管控歷程；確認的細節濃縮在修訂說明，不放正文。
3. 結構：功能目的 → 畫面 → 操作說明 → 規則 → 匯出內容 → 提示。
4. 規則、欄位、格式類內容一律用表格；只有有先後順序的操作步驟用編號清單。
5. 前端檢核（送出前擋下，提示在欄位下方）與後端回應（送出後，提示在訊息區）分開寫；警告訊息用實際畫面截圖呈現，每個前端功能附各種狀態的畫面。
6. 交付格式為 Word（由 md 轉出，圖片嵌入）。

## SD 標準
1. 依 MCP 既有 SD 範本：程式基本資料表、版本管控歷程、目錄、規格說明、API 說明。
2. 章節順序：使用資料表 → 前端功能與 API 對應表 → 共用方法清單（共用方法、位置、類型、被誰使用、說明）→ 共用回應與錯誤碼（含「檢核位置」與「前端提示位置」）→ API 說明。
3. 每個 API 標明控制層、服務層、查詢層的檔案與方法，以及使用的共用方法；不需要獨立的分層對照表。
4. 不可指向內部過程檔案，不可有「選用」這類不確定寫法，不可有說明本文件用途的句子。
5. 資料表欄位不放在 SD，使用資料表只放連結；結構另外寫成資料表結構文件。
6. 交付格式為 md。

## 資料表結構文件標準
有關聯且屬同一業務主題的表（主表加明細表）放同一份 `TableSchema/<主表名>.md`，沒有關聯的表各自一份（檔名為表名）。分組由 DB 設計師判斷，程式只擋明顯不合理：同一份文件內的表之間必須有外鍵（或關聯清單的邏輯關聯）連通。每張 `CREATE TABLE` 必須恰好出現在一份文件的一個小節，不能漏、不能重複。

文件結構（依序）：
1. 標題與「## 本文件包含的資料表」（資料表｜說明；第一列是主表，檔名即主表名）。
2. 「## 版本管控歷程」：整份只寫一次；任何內容（表、欄位、索引、關聯、ER 圖）變動就新增一列。
3. 「## 模組 ER 圖」：Mermaid erDiagram 加轉出的 PNG（`er/<文件名>.png`，相對於文件）。
4. 每張表一節「## 資料表：<表名>」：「### 欄位清單」（涵蓋 SQL 全部欄位）、有索引時「### 索引」、「### 各規格使用欄位對照」。
5. 「## 關聯清單」：表頭固定「子表｜子表欄位｜父表｜父表欄位｜關係｜依據」。依據只能是「外鍵約束」（必須與 SQL 的外鍵一一對得上）或「邏輯關聯」（沒有外鍵約束但程式實際當關聯用；程式只驗格式與表、欄位存在，真偽由規格驗證師對照程式碼確認）。關係只能是「一對多」「一對一」：外鍵欄位剛好是 UNIQUE 或主鍵為一對一，否則一對多。

SD 的「使用資料表」連結寫成 `TableSchema/<文件>.md#<表名>`，錨點等於表名，對應文件內「## 資料表：<表名>」小節。

### ER 圖
- 模組 ER 圖：每份文件一張，畫該文件內的表、全部主鍵與外鍵欄位（標 PK、FK，其他欄位可列可不列）與關聯線。
- 系統 ER 圖：`TableSchema/system-er.md`（含版本管控歷程與「## 系統 ER 圖」，PNG 為 `er/system-er.png`），畫全系統所有表與全部關聯，只列表名加主鍵與外鍵。既有系統含既有的表，本次新建的表在欄位註解標「本次新增」，ALTER 的既有表標「本次修改」。既有表自動取自專案內 .sql 腳本；掃不到時在 system-er.md 加「## 既有資料表」表格（資料表｜主鍵｜外鍵｜說明）。
- 關係符號：父表側外鍵欄位全 NOT NULL 為必選 `||`、否則可選 `|o`；子表側一對多 `o{`、一對一 `o|`；父表在左，例如 `orders ||--o{ order_items`。
- 圖上的表必須等於範圍內的表、關聯線與關聯清單一一對應、圖上的欄位必須存在於 SQL。欄位完整性由欄位清單負責，ER 圖只負責表與關聯。
- PNG 放 `TableSchema/er/`，用 `work_item render`（kind=mermaid，src 為文件）轉出，或用 `attach destDir=er` 手動存放。

## 通用原則
- 正式交付物（SA、SD、資料表結構與 ER 圖、流程圖）必須自足：不指向內部過程檔案，圖片路徑為相對於文件的固定位置。
- 內部過程檔案（SQL 設計說明、規格驗證報告、審查報告、實作說明等）不交付。
